## 2. Intended purpose and operational context

Valora is a TypeScript CLI and MCP orchestration platform for **developer-side** AI-assisted software development. It targets the Limited Risk tier under the EU AI Act.

**Typical workflow:** A developer runs `valora <command>` or invokes a Valora MCP tool from an IDE. Valora orchestrates a sequence of AI agents (each with a scoped persona and permitted tool set) to produce a result. Results are presented to the developer for review before any real action (file write, git operation, deployment step) is taken.

## 3. Architecture overview

See [system-architecture.md](system-architecture.md) for the full component diagram.

Key structural properties:

- **Two binaries:** `valora` (CLI) and `valora-mcp` (MCP server for IDE integration).
- **Layer direction enforced:** `Types → Config → Repo → Service → Runtime → UI`. Violations are caught at lint time.
- **Human escalation gates:** The `EscalationHandlerService` pauses the pipeline and presents structured choices (Proceed / Modify / Abort) whenever a risk threshold is crossed. The gate is fail-closed: a stage response missing or malformed the mandatory escalation block is itself treated as an escalation (`EscalationDetectionService.getMissingSignalEscalation`), rather than silently proceeding. See §7 for how much the underlying confidence number itself can be trusted.
- **Session isolation:** Each command runs in an `ExecutionContext` with a scoped tool set; agents cannot access tools outside their declared capability set.

## 7. Known limitations

- **Hallucinations.** LLM outputs may contain factually incorrect statements. All outputs require human review.
- **Self-reported confidence is not independently verified in the general case.** The escalation gate's `confidence` value (0–100) is stated by the model itself in a mandatory `_escalation` JSON block; nothing computes or checks it against ground truth for most of its range. Mitigations, and their honest limits:
  - A missing or malformed confidence value forces escalation rather than being trusted (`EscalationSignal.confidenceSource: 'defaulted'`) — this closes the "silently skip review" failure mode, but does not validate a _present_ value.
  - `SelfConsistencySamplerService` independently re-samples the model (2 extra calls by default) only when confidence sits just above the escalation threshold and the model reports no escalation needed — the single highest-risk case for a boundary that's about to let a stage skip review. Outside that narrow band, no independent check runs.
  - `StageExecutor.checkExecutionTelemetryMismatch` cross-checks a confident report against the stage's own tool-loop telemetry (exhausted iteration budget, failed mutating tool calls) — free, and applies to every escalation-gated stage, but only catches cases where execution itself visibly struggled; a model that is confidently wrong about a stage that ran cleanly is not caught by this.
  - `EscalationLedger` durably records every escalation decision (confidence, risk level, and the human's actual choice) so that calibration can be assessed empirically over time via `valora monitoring confidence-report`, rather than assumed. This is retrospective, not a real-time correctness guarantee, and does not yet correlate a decision with what happened to the output _afterward_ (reverted, reworked) — only with the immediate human decision.
  - None of the above establishes that "confidence: 85" corresponds to 85% empirical accuracy; that would require calibration measurement against ground-truth outcomes over many runs, which has not been performed.
- **Model drift.** Upstream provider model versions may change silently; the behavioural regression suite (Phase 4) detects this but requires periodic baseline refresh.
- **Prompt injection.** Malicious content in tool results (e.g. a compromised dependency README) could attempt to override agent instructions. The `PromptInjectionDetector` reduces but does not eliminate this risk.
- **Agent collusion.** Two agents exchanging information via shared memory could theoretically coordinate to bypass a policy. This is mitigated by the permission intersection rule (Phase 4) but warrants monitoring in high-assurance deployments.
- **No real-time content moderation.** Valora forwards prompts to upstream providers without an intermediate moderation layer. Deployers inherit upstream content policies in full.

## 8. Risk classification rationale

Valora is classified **Limited Risk** because:

- It operates exclusively in a developer toolchain context, not in a public-facing or consumer product.
- All outputs have a mandatory human review step before any real-world action is taken.
- It does not process biometric, medical, financial credit, or law-enforcement data.
- It does not make autonomous decisions in any Annex III domain.

Conditions that would tip to **High Risk:** using Valora to automate decisions in an Annex III domain (e.g. automated HR screening, clinical decision support) without additional conformity assessment and human oversight measures.

## 9. Safety and oversight controls

| Control                         | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Human escalation gates          | `EscalationHandlerService` — required for all risk-level findings; fail-closed on a missing/malformed signal                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Self-consistency verification   | `SelfConsistencySamplerService` — re-samples the model when confidence is borderline and no escalation is claimed                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Execution-telemetry cross-check | `StageExecutor.checkExecutionTelemetryMismatch` — confidence claim checked against actual tool-loop outcomes                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Confidence calibration ledger   | `EscalationLedger` / `ConfidenceCalibrationAnalytics` — durable record for empirical trust assessment over time                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Credential redaction            | `CredentialGuard` — redacts before any log or trace output                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Command injection prevention    | `CommandGuard` — blocks dangerous shell patterns for agent-issued shell commands. Does **not** cover MCP stdio server launches (`command`/`args`/`env` in `mcps.json`) — those are plugin-trusted content by design, not agent-issued commands, and are instead covered by `ToolIntegrityMonitor`'s rug-pull fingerprinting (see below) and `mcp-server-config.schema.ts`'s shape validation                                                                                                                                                               |
| Prompt injection detection      | `PromptInjectionDetector` — scores and flags suspicious tool results                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Tool integrity monitoring       | `ToolIntegrityMonitor` — detects tool-set drift (rug pull)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Permission intersection         | `PermissionPropagationService` (Phase 4) — child agents cannot exceed parent scope for `forbidden_paths`, enforced end-to-end from persona-file declaration (`ExecutionCoordinator` loads the agent and wires its constraints into the root `ExecutionContext`) through `ToolExecutionService`. `requires_approval_for` is parsed and propagated but not yet mechanically enforceable for semantic-category values (e.g. `encryption_key_operations`) — only path-shaped patterns match today; category-based approval gating is tracked as follow-up work |
| Deterministic validation        | `StageValidationService` + validator registry (Phase 2) — LLM "all clear" cannot bypass a deterministic fail                                                                                                                                                                                                                                                                                                                                                                                                                                               |

See `.claude/CLAUDE.md` for developer-facing escalation rules.
