# EU AI Act Compliance — Instructions for Use

> **Regulation:** EU AI Act (Regulation (EU) 2024/1689), Article 13 — Transparency and provision of information.
> **Risk classification:** Limited Risk (Article 50 transparency obligations apply).

## Intended purpose

Valora is a **developer-side CLI and MCP orchestration platform** for automating software development lifecycle tasks. It is intended for use by professional software engineers and teams to:

- Plan, scaffold, and review code with AI agent assistance.
- Orchestrate multi-step pipelines (requirements analysis, code generation, security review, documentation).
- Integrate AI assistance into development toolchains via the MCP protocol.

All AI-generated outputs are intended to be **reviewed and approved by a human developer** before being acted upon. Valora is not intended for autonomous production deployment without human oversight.

## In scope

The following use-cases are explicitly in scope and supported:

| Use-case                           | Notes                                                    |
| ---------------------------------- | -------------------------------------------------------- |
| Code generation and review         | All outputs require developer review                     |
| Requirements analysis and planning | Advisory; human decision-maker required                  |
| Security review (SecOps agent)     | Identifies risks; does not make final security decisions |
| Documentation generation           | Review required before publishing                        |
| Automated testing assistance       | Test plans require human validation                      |

## Out of scope — domains requiring additional controls

The following domains are **explicitly out of scope** without additional human review controls and organisational governance. Using Valora in these contexts without such controls would risk non-compliance with EU AI Act Annex III high-risk categories:

| Domain                                         | Annex III reference | Why out of scope                                                             |
| ---------------------------------------------- | ------------------- | ---------------------------------------------------------------------------- |
| Employment / HR decisions                      | Annex III §4        | Agent outputs must not directly trigger hiring, firing, or promotion actions |
| Biometric processing or identification         | Annex III §1        | Valora does not process biometric data and must not be configured to do so   |
| Law enforcement or predictive policing         | Annex III §6        | Not approved for use by law enforcement bodies                               |
| Medical diagnosis or clinical decision support | Annex III §5b       | Agent outputs are not clinically validated                                   |
| Financial credit scoring or risk assessment    | Annex III §5b       | Agent outputs are not audited financial instruments                          |
| Education assessment or grading                | Annex III §3        | Outputs must not be used as the sole basis for student assessment            |

## Deployer obligations

Organisations deploying Valora must ensure:

1. **Human in the loop.** Every compliance-critical agent output must be reviewed by a qualified human before the action is taken. Valora provides escalation gates; deployers must not bypass them.
2. **Audit log retention.** Session logs and security audit events must be retained per the organisation's data retention policy. Use `valora security audit-export` to generate periodic snapshots.
3. **Special-category data prohibition.** Do not include Article 9 GDPR special-category data (health, ethnicity, political opinions, religion, trade union membership, genetics, biometrics, sex life, sexual orientation) in prompts or context passed to any Valora agent or LLM provider.
4. **Provider policy compliance.** Deployers inherit the upstream GPAI provider's usage policies in full. See [GPAI Upstream Policy](../developer-guide/gpai-upstream-policy.md).
5. **Incident reporting.** Material security incidents or serious malfunctions must be reported via the process in [SECURITY.md](../../SECURITY.md).

## AI disclosure

Every Valora output carries an AI disclosure footer in human-readable (Markdown) output mode:

```
AI-generated by Valora vX.Y.Z. Review before use. EU AI Act Art. 50.
```

This can be suppressed for machine-readable output (`--output json`/`yaml`) or explicitly with `--no-disclosure` / `VALORA_NO_DISCLOSURE=1`.
